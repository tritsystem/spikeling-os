Build recipe for `kernel/assets/cc.elf`, Milestone 67/68/69's real, externally-
built ELF64 test executable -- Tier 3's first three slices: a subset-C lexer +
minimal recursive-descent parser (Milestone 67), real x86_64 machine-code
generation from the resulting AST (Milestone 68), and a real, from-scratch
ELF64 *writer* + the kernel's own real exec() (Milestone 69) -- exercising the
exact grammar documented at the top of `main.rs` (single genuine `PT_LOAD`
segment at `USER_CODE_ADDR`, built with this project's own pinned Rust nightly
toolchain + `rust-lld`, not hand-assembled -- same recipe as every other
tools/*_src build).

```
rustup run nightly-x86_64-pc-windows-gnu rustc --target x86_64-unknown-none \
    -C link-arg=-Ttools/cc_src/linker.ld \
    -C link-arg=--gc-sections -C link-arg=-znoseparate-code \
    -C link-arg=-zmax-page-size=16 \
    -C code-model=large -C relocation-model=static \
    -C panic=abort -C opt-level=z --crate-type bin \
    tools/cc_src/main.rs -o kernel/assets/cc.elf
```

Same flags, same reasons, as `tools/stdiotest_src/README.md` (`--gc-sections`
to drop unused wrappers this program never calls -- this program's own
`libc.rs` is a copy of `tools/stdiotest_src/libc.rs`'s non-stdio portion
(sys_write/sys_exit/malloc/free/string.h). As of Milestone 69, this program
actually calls `sys_write`, `sys_exit`, `malloc`, `sys_open`, `sys_fdwrite`,
`sys_close`, `sys_fork`, `sys_wait`, `sys_exec`, `memcpy`, and `memset` (real
uses, not dead code -- see main.rs's own Milestone 69 section) -- only
`sys_read`, `free`, `memmove`, `memcmp`, `strlen`, `strcmp`, `strncmp`,
`strcpy`, `strncpy`, `strcat`, `strchr` remain genuinely unused, `never used`
warnings expected and harmless, matching every prior tools/*_src build's own
disclosed warning set).

**Milestone 69 addition**: a real, from-scratch ELF64 *writer*
(`build_elf64_standalone()` in `main.rs`) wraps `CodegenMode::Standalone`
output (a new codegen mode ending in a real `sys_exit()` sequence instead of
`leave; ret`) in a real, minimal ELF64 image, written to the real on-disk
filesystem via ordinary `open()`/`fdwrite()`/`close()` syscalls, then run
through the kernel's own real, pre-existing `exec()` syscall (Milestone
36/45, completely UNCHANGED by this milestone) via a real `fork()`+`exec()`+
`wait()` sequence (`write_exec_and_check!` macro in `main.rs`) -- self-tested
by checking the REAL exit code the kernel's own `wait()` syscall reports for
the freshly-exec()'d child, not just that it ran. This is Tier 3's strongest
verification yet: cc.elf compiles subset-C source, writes a genuine
standalone ELF64 executable to disk, and the kernel's own unmodified exec()
path runs it as a completely separate process. See README.md's own Milestone
69 entry for the full design reasoning, the two real, pre-existing kernel
bugs this milestone found and fixed along the way (fork() silently dropping
a multi-page process's code pages beyond page 0; the forked-child ring-0

**Milestone 71 addition**: real `while`-loop codegen (`STMT_WHILE` in
`main.rs`) -- the one genuinely new real x86_64 encoding is
`CodeBuf::emit_jmp_back()`, an unconditional `jmp rel32` whose target is a
BACKWARD reference (the loop-condition re-check, already emitted by the
time the loop body finishes) rather than the forward references every
prior jump in this file needed a placeholder-then-patch two-step for; the
loop's own forward "exit when false" branch reuses Milestone 70's
`emit_jz_placeholder()`/`patch_rel32()` machinery completely unchanged.
Self-tested four ways: an ordinary sum-1-to-5 loop (both the backward jmp
and the forward exit jz actually taken), a zero-iteration loop (condition
false on the very first check, proving the exit jz alone is correct when
the backward jmp is never reached), an `if` nested inside a `while`
(Milestone 70 and 71 control flow combined in one program), and the same
sum-loop program run through the real on-disk-ELF + kernel `exec()` +
`wait()` path Milestone 69 established -- the strongest verification tier,
same as Milestone 70's own CASE 17/18. See README.md's own Milestone 71
entry for the full design reasoning and the real, quoted serial-log
evidence from both a fresh-disk and a reused-disk boot.

**Milestone 72 addition**: real function parameters and function calls
(`gen_program()`/`parse_program()`/`parse_params()` and the `EXPR_CALL`
codegen arm in `gen_expr()`, all in `main.rs`) -- a real x86_64 calling
convention (integer arguments 1-4 in RDI/RSI/RDX/RCX, extending this
kernel's own real syscall-ABI register ordering rather than inventing a
new one), real per-function stack frames (`CodeBuf::emit_mov_rbp_off_reg()`
spills each incoming argument register to its own rbp-relative slot in the
callee's own prologue), and real call-site codegen
(`CodeBuf::emit_pop_reg()`/`CodeBuf::emit_call()` -- push every evaluated
argument, pop them back in reverse into the argument registers, a real
`call rel32` to an already-compiled callee, reusing Milestone 71's own
"target already known, single-pass, no placeholder/patch" technique).
Honestly scoped: `program := function+` up to 4 functions, up to 4 integer
parameters per function/arguments per call, a callee must be defined at or
before its own caller in source order (no forward calls, no mutual
recursion; direct self-recursion is mechanically reachable by this codegen
but not tested or verified). Self-tested six ways: a real multi-function
AST-shape check; an ordinary 2-parameter call whose result is only correct
if both arguments were passed and read in the right order (`combine(7,5) =
7*10+5 = 75`); the same idea generalized to 3 and 4 parameters (exercising
RDX and RCX); a call used as another call's own argument expression,
combined with a local variable argument; the same 2-parameter program run
through the real on-disk-ELF + kernel `exec()` + `wait()` path Milestone 69
established -- the strongest verification tier, same as Milestone 70/71's
own precedent; and a deliberate semantic error (a call to an undeclared
function name) proving the new `CodeGenError::UndeclaredFunction` path is
real. See README.md's own Milestone 72 entry for the full design reasoning
and the real, quoted serial-log evidence from both a fresh-disk and a
reused-disk boot.

**Milestone 76 addition**: real grammar growth -- unary minus
(`unary := "-" unary | factor`, slotted directly above `factor` so it
binds tighter than `*`/`/` and, transitively, `+`/`-`; one new CodeBuf
encoding, `emit_neg_rax()`) and the two real short-circuit logical
operators `&&`/`||` (`logic_and := cond_expr ("&&" cond_expr)*`,
